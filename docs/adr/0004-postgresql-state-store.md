# ADR 0004: PostgreSQL as State Store

## Status
Accepted

## Context
ShipIt Platform needs durable, queryable, transactional storage for:
- Products, work items, workflow state
- Design contracts, human decisions (auditable)
- Agent results, QA evidence, deployment records
- Complex queries (filtering, aggregation, reporting)
- ACID guarantees for state transitions
- Local development parity with production

## Decision
**PostgreSQL** is the primary state store, accessed via Serverpod ORM.

## Rationale

| Requirement | PostgreSQL Fit |
|-------------|----------------|
| ACID transactions | ✅ Full support |
| Complex queries | ✅ SQL, JSONB, indexes |
| JSON storage | ✅ JSONB for flexible schemas |
| Durability | ✅ WAL, replication |
| Local dev parity | ✅ Docker image identical to prod |
| Serverpod integration | ✅ Native ORM target |
| Cost (managed) | ✅ Cloud SQL, RDS, Neon, Supabase |
| Team familiarity | ✅ Standard SQL knowledge |

Alternatives considered:
- **MongoDB**: Weaker ACID, no Serverpod ORM, schema drift risk
- **SQLite**: No concurrent writer parity with prod, no JSONB indexing
- **Event store (EventStoreDB)**: Overkill, adds complexity, no Serverpod
- **Firestore/DynamoDB**: Vendor lock-in, limited query flexibility
- **In-memory + snapshots**: Not durable, loses audit trail

## Consequences

### Positive
- Strong consistency for workflow state transitions
- Rich querying for dashboard, reporting, debugging
- JSONB allows schema evolution without migrations for flexible fields
- Serverpod generates type-safe queries from Dart
- Identical local (Docker) and production (Cloud SQL) behavior

### Negative
- Operational overhead (backups, scaling, migrations)
- Connection pooling required at scale
- Schema changes require migrations

### Mitigation
- Use managed PostgreSQL in production (Cloud SQL)
- Serverpod handles connection pooling
- Migrations version-controlled, reviewed in PR
- Read replicas for dashboard queries

## Schema Strategy

```
Core Tables (Serverpod-managed):
- product
- work_item
- design_contract
- human_decision
- agent_session
- agent_result
- qa_gate
- qa_evidence
- deployment_artifact
- deployment_record

Flexible JSONB columns:
- work_item.metadata
- agent_result.diagnostics
- qa_evidence.content
- deployment_record.result
```

- Core columns: indexed, foreign keys, NOT NULL
- JSONB columns: for extensible payloads, GIN indexes where queried
- All timestamps UTC, `timestamptz`
- UUID primary keys (Serverpod default)

## Migration Policy
- All migrations in `control_plane/server/generated/migrations/`
- Generated by `serverpod create-migration`
- Reviewed in PR, applied on deploy
- No direct SQL in application code
